### Analysis run

State: progressing. Runs one figure or table of an analysis from **Analysis plan** and records where it came from. Only `scripts/rstack_run.py` (in the `research-mode` skill folder) writes provenance; do not run a figure script by hand. The runner enforces the rules below, so a step that is skipped fails with an error that names the fix.

One task in the README is one figure or table is one script (`scripts/<figure>.py`) is one provenance folder (`.rstack/provenance/<analysis>_<figure>/<timestamp>/`). The task text names the figure. Each figure also has an Objective and a Why in `docs/method.md`; the runner refuses a run without them, so the page and the results file can say what the figure is for.

Principles for the figures: `principle-frame-follows-the-data`, `principle-color-means-one-thing`. Skills for this playbook: `figures` (the drawing rules and figrecipe), `acceptance-checks` (the checks), `statistical-analysis` (the test), `uncertainty-and-units`, `scientific-critical-thinking` (to read a result without over-reading it), `show-me-your-work` (the trail).

Templates: scripts start from `templates/analysis/figure.template.py` and `figure.checks.template.py` (made by `rstack_run.py new`), the shared helpers from `templates/lib/` (`rstack_run.py lib`). Fix a bug in the template and in the project copy.

**The loop, per task**

1. **Gate.** Take the next open task, working through `### Check`, then `### Main`, then `### Verify`. The runner refuses a run with no task of its own, a main-stage run while a check task is open, and a verify-stage run while a check or main task is open. Fix it by running the earlier tasks, never by editing around it. If the README lacks a Tasks section or the plan is not approved, go back to **Analysis plan**.
2. **Prepare.** Check `docs/method.md` gives the figure an Objective and a Why (the runner refuses otherwise). Before running, confirm with `acceptance-checks` that `scripts/<figure>.checks.py` exists and turns the plan's criteria into executable checks: the README hypothesis table, **Checks** in `docs/method.md`, the figure rules, units and counts. Write the check before the script runs; it is the oracle. Choose the inputs: the ids the task names, or ask. A different selection is a new run.
3. **Run.** `rstack_run.py run analysis/<name> --stage check|main|verify --figure <figure> --ids a,b --note "<one line>"`. The interpreter defaults to `tools/figrecipe/.venv/bin/python` above the project (else pass `--python`); the runner refuses an interpreter that cannot import figrecipe, matplotlib and pandas. The script draws with the `figures` skill, through `analysis/lib/style.py`. The runner then copies everything into the provenance folder:
   - `inputs.yaml` (selected files with sha256; raw data is hashed, never copied), `scripts/`, `lib/` (the project's `analysis/lib/`, hashed in `run.yaml`; replay uses this copy), `inputs/` (copies of derived inputs up to 5 MB; raw files are only hashed), `config/` (the preset the script loaded)
   - `env.txt` (python, packages, git commit, raw-viewer version), `command.txt`, `log.txt`
   - `outputs/` (the figure folder and tables this run wrote), `checks.txt`, `style_overrides.json`
   - `run.yaml`: stage, status, selected ids, sha256 of each output, problems, style overrides, warnings, the note
4. **What the runner rejects.** Status rejected when the script writes outside `figures/<figure>/` and `tables/<figure>*`, or leaves a figure without `<figure>.yaml`, `<figure>_data/` and a png or pdf. failed when the script errors. check-failed when the checks fail. completed when no checks script exists, which can never be ticked. Only verified gets `figures/<figure>/run.txt`. A failed run is kept in its own folder; `figures/` and `tables/` go back to how they were, so a bad run never leaves files there. Fix and run again. A run after a change (a parameter, another input selection, a script) is a new run of the same figure with its own provenance; compare it with `rstack_run.py diff` (see **Analysis review**, Changed run). A new run never overwrites an old one.
5. **Audit.** Read the result before judging it: status, warnings (an input changed since the last run, a style override, `.rstack/` git-ignored), `log.txt`, the figure, and the numbers against the expected evidence. Observations only; write them in the run note, not interpretations. Separate what the figure shows from what it would take to assert (`scientific-critical-thinking`): n, what the spread is, pseudoreplication, multiple comparisons, selection. Put a suspicion in the run note as a question, never as a conclusion. A check-stage run that finds something the plan did not foresee goes in **Deviations** in `docs/method.md`.
6. **Figure rules**, diagnostic figures too, checked by `save_figure` (`lib/figrules.py`) before saving:
   - no title; the caption carries the claim
   - 3 to 5 major ticks per axis
   - decimal tick labels, never `1e-6` style; scale the unit with `figrules.si_scale` (µ, n, m, k)
   - label every axis with a quantity and unit
   - overlay individual measurements on means and error bars; state n and what the spread means
   - preset from `config/`; no colour that is not in the project's colour file
7. **Verify.** A verified run passed the checks. Then `rstack_run.py check analysis/<name>` (each figure file still matches its run) and `rstack_run.py replay .rstack/provenance/<analysis>_<figure>/<timestamp>`. Replay reruns the saved scripts on the saved selection, refuses if an input changed, and compares `<figure>_data/` and the tables with the original. A replay that does not reproduce means a missing seed or a changed environment; stop and find out which.
8. **Show the user.** Show the figure, `checks.txt` and any style override (a line width or marker size that differs from the preset; allowed, but say why). The user decides.
9. **Tick: your sign-off.** Until you say OK, the figure is only machine-checked. After the user's ok: `rstack_run.py tick analysis/<name> --figure <figure> --approved-by-user`. It needs a verified run and does three things: ticks that task in the README, adds the run to the **Runs** table, and writes `docs/results/<figure>.md` (the objective, run, inputs, figure path, and a claim for you to fill in with n and what the spread is). Run again after a tick and it records a re-run: the new run replaces the result, the claim is kept to re-check, and the old run is listed as superseded. Never pass the flag before the user has seen the figure. Log the run in `docs/rstack/decisions.tsv` (**show-me-your-work**). When the last task is ticked, tell the user so **Task tracking** can tick the analysis in `tasks.md`.
9a. **Look back at everything.** `rstack_run.py show analysis/<name>` writes `analysis/<name>/provenance.html`: one card per figure in task order, with the objective, why, the figure, the claim, and tabs for runs, inputs, checks, code, log and environment. It reads stored files only and runs nothing. To prove a figure still reproduces, use `replay` on its run folder.
9b. **Export for a paper or slide.** `rstack_run.py export analysis/<name> --figure <figure>` copies the accepted run's png and pdf into `manuscripts/figures/` (or `--out DIR`) as `<run id>_<figure>.png`, after checking them against the run's recorded hashes. The file name is the provenance folder name, so a copy anywhere says which run made it. The live `figures/<figure>/<figure>.png` keeps its stable name; manuscripts that must not change on a re-run include the exported file.
10. For a sensitivity check, vary one analysis choice in a new run and compare. Report n, spread, and effect sizes, not only p-values. Correct for multiple comparisons when many are tested.

**Reply:** run id, status, what the audit saw, replay result, and whether the task is waiting for the user's ok.
