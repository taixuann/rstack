### Paper preparation

Phase: write, stage: prepare. Output: `docs/reports/<question>/` complete for the target and approved by the user. Principles: `principle-ask-do-not-fill`, `principle-report-before-prose`. Skills: `interrogate` (interview mode), `venue-templates`, `citation-management`, `scientific-critical-thinking`, `number-check`, `show-me-your-work`. Reads `docs/reports/<question>/` (README, design, log), `analysis/<name>/docs/results/`, `docs/literature-review/`. Writes `docs/rstack/writing/<piece>/`, `docs/reports/<question>/`.

1. **Target interview.** Use `interrogate` in interview mode, short rounds. Ask for the kind, venue, article type, submission stage, audience, length, and the key message as one sentence in the user's words. One paper carries one central contribution; if the user gives two, ask which one this paper is about. Write the answers to `docs/rstack/writing/<piece>/target.md`, labelled `[user]`.
2. **Venue rules.** With `venue-templates`, open the venue's official author instructions for this article type and stage. Record the URL and the date checked in `target.md`, then the limits: words or pages, abstract, figures and tables, references, required sections and statements, anonymity. A rule not found on the official page is `TODO: unknown`.
3. **Choose the claims.** List the accepted results the analysis has. The user picks which ones this paper makes, by id. Write the ids to `target.md`.
4. **Walk the checklist.** Open `references/paper-checklist.md`. For each item write in `target.md` where it comes from: a report entry id, a `[user]` answer, or `TODO: unknown`. This list decides which evidence files are needed and what each must hold.
5. **Build the report.** Write the files of `docs/reports/<question>/` following `references/report-schema.md`, from rstack's outputs: `analysis/<name>/docs/results/<figure>.md` for each accepted figure, the analysis package, the method notes, the literature notes. Every entry names the file it comes from as its `source`. A number is written exactly as that file has it, as a quoted string; the report check opens the source and fails when the value is not there, so never type a number from memory, round it, or convert it. Show the user every entry; an entry the user has not confirmed stays out. Never take a number, unit or uncertainty from a chat answer.
6. **Interrogate each claim.** One claim at a time, show the statement, its numbers and its figure. With `scientific-critical-thinking` ask: is the wording stronger than the data (n, spread, scope), does it say cause where the data show association, what would a referee attack first, which limitation belongs beside it. The user answers in their own words. Record limits in `limitations.md` labelled `[user]`. The user decides the wording of every statement.
7. **Citations.** For each work the paper will cite, `citations.yaml` holds the key, the DOI, and what the work is cited for, taken from the literature notes with its page. Use `citation-management` to turn DOIs into BibTeX and to validate `docs/writing/<piece>/references.bib`. A citation with no checked support is `TODO: unknown`.
8. **Ask every TODO.** One topic at a time. Metadata answers go into `target.md` labelled `[user]`. A missing measurement goes into `docs/rstack/writing/<piece>/todo.md` with an owner, as a task for the analysis.
9. **Check.** Run `number_check.py report <project> <piece>`. Fix what it names and run it again. Never make it pass by editing an analysis file.
10. **Gate.** Show the user the checklist status and the check output. When the user says the report is approved, run `writing.py gate <project> <piece> report-approved --approved-by-user`. It runs the check again, freezes the report and sets the stage. Log each claim that was dropped or reworded in `docs/rstack/writing/<piece>/decisions.tsv` with `show-me-your-work`. If the report must change later: `gate ... back-to-prepare`, on the user's word.

**Reply:** the target in three lines, the claims chosen, the checklist items still open with their owner, the check result, and whether the gate passed.
