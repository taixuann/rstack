### Paper writing

Phase: write, stage: write. Output: the user's text in `docs/writing/<piece>/sections/`, one `.tex` file per section, pulled together by `main.tex`. Principles: `principle-the-user-writes-the-prose`, `principle-fixes-need-a-yes`. Skills: `interrogate` (interview mode), `number-check`, `venue-templates`, `academic-humanizer`. Reads `docs/reports/<topic>/`, `docs/rstack/writing/<piece>/`. Writes `docs/rstack/writing/<piece>/` control files only; the user writes `docs/writing/<piece>/`.

1. **Check the gate.** `writing.py status <project> <piece>` says `stage: write` and the report is approved and unchanged. Otherwise stop and name the open gate. If `docs/writing/<piece>/` has no `main.tex`, ask the user for the venue's template (`venue-templates` can find the official one) and set up `main.tex` with one `\input` per section. That file holds no prose.
2. **Main points first.** Before any paragraph, use `interrogate` in interview mode. Ask the user to state the central contribution, then the main points of each section, one line each. Go in this order: figures, results, methods, introduction, discussion, then abstract and title last. Write the user's lines verbatim to `docs/rstack/writing/<piece>/scaffold/outline.md`, labelled `[user]`. Ask until every chosen claim has a point, every point names the report entries it rests on, and the points read as one line of argument. A point with no report entry is a gap: say so.
3. **Scaffold a section.** Write `docs/rstack/writing/<piece>/scaffold/<section>.md`: the heading, the user's main points for it, and under each point the questions its paragraph must answer (what the reader must know first, what the content is, what it means), the report entries by id with value and unit copied, and the venue limits for the section. No sentence of manuscript prose.
4. **The user writes** `docs/writing/<piece>/sections/<section>.tex`.
5. **Develop by questions.** Read the user's section. For each main point ask: where is its context, where is its evidence, where is its conclusion. Name each sentence that has no report entry behind it, and each scaffold question left unanswered. Ask where a reader who does not know the work would be lost. When the user asks how a passage reads, audit it with `academic-humanizer` and give the findings. Put every item as a question. Do not rewrite, and do not offer a replacement sentence.
6. **Check the numbers.** Run `number_check.py draft <project> <piece> docs/writing/<piece>/sections/<section>.tex`. Show every FAIL with its line. A number that is not in the report is added by the analysis and Paper preparation, never by changing the report here.
7. **Mechanical fixes.** List citation format, unit format and typos, one per line: file, line, before, after. Apply only the ones the user accepts.
8. **Gate.** When the user says the draft is ready for critique, run `writing.py gate <project> <piece> draft-ready --approved-by-user`.

**Reply:** the sections written, the open questions per section, the number-check result, the fixes proposed and accepted, and whether the gate passed.
