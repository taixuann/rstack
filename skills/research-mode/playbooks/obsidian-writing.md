### Obsidian writing

State: any. Use whenever you write a note the user reads and comments on in Obsidian: a learning session, a paper README, an alignment, a cross-paper note. Done means the note opens in Obsidian with its figures showing, the user's comments untouched, and `scripts/check_references.py` passes.

The user reads these files beside the paper and comments in them. The file is the conversation, so the chat reply stays short.

1. **Place it.** One home per kind: `docs/literature-review/papers/<cite>/` for one paper, `docs/literature-review/cross-papers/` across papers, `docs/inputs/` for the user's own words. Start the file with front matter: `created`, `updated`, `kind`, `voice`, and `paper` when it belongs to one. Link other files with relative links. Embed figures with `![[figures/<name>.svg]]`, with the figure in a `figures/` folder next to the note.
2. **Write for a reader who is new.** Short sentences. Define a term where it first appears. Say what a word points at before using it. Label statements with the understanding ladder. Put the user's own words in quote blocks marked `[user]`, copied word for word.
3. **Draw with Pele, not Mermaid blocks.** Write the diagram as Mermaid text in `figures/<name>.mmd`, then run `node scripts/render_diagram.mjs figures/<name>.mmd`. It writes `figures/<name>.svg` with the vendored Pele (`vendor/pele/`, MIT, Node 20 or newer). Embed the SVG. Do not leave a `mermaid` code block in a note. Keep the `.mmd` as the source. A picture Mermaid cannot draw (a cell with ions, a circuit) is an SVG drawn by hand in the same folder. In both cases render it to PNG (`rsvg-convert -w 1000 x.svg -o x.png`) and look at it before the user does.
4. **Leave the user's comments alone.** The Document Comments plugin stores a comment as `<!--c:ID-->quoted text<!--/c:ID-->` in the text and a thread block `<!--co:ID by:NAME at:ISO status:open quote:"..."` then one `name (ISO-time): text` line per message, then `-->`. Reply by adding one line `claude (<UTC ISO time>): <text>` before the closing `-->`. Keep it on one line and do not start it with a word followed by a colon. Never resolve, delete, or move a thread. The user edits the file while you work, so read it again before each change and change only the exact lines you mean to. Never rewrite a whole note from memory.
5. **Check.** Run `scripts/check_references.py docs/literature-review/references.yaml`. It fails on missing front matter, a `mermaid` block, an embed that points at nothing, a `.mmd` newer than its `.svg`, and unbalanced comment markers, and each error names the fix.
6. **Hand back.** Tell the user the file path and the one thing to read or answer next, in three lines or fewer. Do not restate the note in chat.
