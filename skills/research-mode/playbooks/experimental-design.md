# Experimental design

Output: design note at `analysis/design/<yyyy-mm-dd>_<name>.md`.

Load these skills only as needed:
- `hypothesis-generation` or `scientific-brainstorming` when the question is not yet sharp; `brainstorming` to choose between directions; `what-if-oracle` to stress scenarios.
- `experimental-design` for the design itself: groups, randomisation, blinding, controls, confounders.
- `statistical-power` for sample size. Run the calculation in code and record the inputs.
- `uncertainty-and-units` when measurements carry physical units or instrument error.
- `scientific-critical-thinking` to attack the finished design; `interrogate` for a stronger adversarial pass; `arena` when two or more designs are plausible.

The note contains: one primary question and a falsifiable hypothesis, with what would refute it; variables and primary endpoint; the design with a short tradeoffs table against the best alternative; sample size with effect-size source, alpha, power, dropout; protocol and the data to record (and where it lives in `data/`); the pre-stated analysis plan that study-analysis will consume; risks and fallbacks.

Discussion mode: argue the strongest alternative design before settling; push back on weak controls or underpowered plans.
