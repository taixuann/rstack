### Notion writing

State: any. Use whenever you write a lesson or learning note the user reads and comments on in Notion: a teach lesson or an explain account. The user writes the page; `evaluate-my-understanding` may add a short Understanding check block at its end under the same rules. Notes about a paper (README, alignment, source analysis) stay in the repo and follow the Obsidian writing playbook. Done means the page opens in Notion with its diagram showing, the user's comments untouched, and its Type and Relation properties set.

The user reads these pages beside the paper and comments on them. The page is the conversation, so the chat reply stays short. The Raw, Log and Map-of-content structure is run by the `notion-llm-wiki` skill. This playbook says how to write a page that lives there.

1. **Find the wiki, do not guess it.** Search Notion by title for the pages Raw, Log and the topic's Map of content page. If any is missing, run the initialization of the `notion-llm-wiki` skill. If that skill is not installed, say so and stop. Never write page IDs, workspace URLs or names into rstack files: rstack is mirrored publicly.
2. **Place it.** A lesson or core note is a Raw page, a child of the Raw page, titled with the date and a slug (2026-11-05_ecg-device-types). A big branch is its own Raw page. The user writes the page; follow `references/raw-lesson.template.md` for the loop. A header with State, Continues and, for a branch, Parent and Depth is enough. No front matter. After creating the page, set its properties with an update; creating it with properties does not set them: Type raw for a Raw page, Type MOC for the roadmap and understanding pages, and Relation pointing at the topic's Map of content page. Read the page back and check that both show. If the Type option you need is missing in the database, report it once and stop; do not retry.
3. **Write for a reader who is new.** Follow `references/plain-writing.md`: short sentences, one word for one meaning, active voice. Define a term where it first appears. Say what a word points at before using it. Label statements with the understanding ladder. Put the user's own words in quote blocks marked `[user]`, copied word for word. Write one flowing account, not boxes: define each term in the sentence where the thing first happens, with its rule or number in the same paragraph. No Definitions or Properties callouts, no list of words before the story (the `explain` skill).
4. **Draw rarely, in a `mermaid` code block.** One figure per page by default, a second only if words and the first cannot show the structure, never one per step (the `make-the-figure` skill). Notion draws a mermaid code block, so write the Mermaid text straight into the page. Keep labels short. A picture Mermaid cannot draw needs a file upload; ask the user before making one.
5. **Open and closed.** While a Raw page is open, the user writes in it and you help in chat. A branch opens as a new Raw page whose header has Parent (the page it came from) and Depth (parent's plus one, at most 3). The user's `[user]` quotes are never edited. When the page is ingested (the `notion-llm-wiki` skill), its State flips to closed, a Log entry says so, and nothing in it changes afterwards. The next lesson on the topic opens a new Raw page whose Continues line links back.
6. **Draft, literature, permanent.** Answer the user's questions in chat, then make small edits to the draft parts the answers change, in the user's structure (see `references/raw-lesson.template.md`). Never restructure, never make a massive edit. Read the open comment threads with the Notion get-comments tool before you edit. Never delete or reword a comment yourself.
7. **Edit a commented page carefully.** Use the update-content command with small exact strings. Never use the replace-content command. Tested 2026-11-05: when update-content replaces text that a comment points at, Notion deletes the whole thread, with every reply. Tested the same day: the resolve tool is not available without a Business plan, so threads stay open until the user resolves them. So copy every comment into My words first, and tell the user which threads the edit removes. Edit text that has no comment by preference. Before an edit, fetch the page with discussions included to see where the comments are anchored.
8. **Keep data off the page.** Lesson text only. If the user pastes recordings, signals, subject identifiers or file listings, do not copy them into Notion; say they stay local, as the project's AGENTS.md requires.
9. **Check.** No script checks a Notion page. Read it back: the properties show, the Mermaid block shows, the comment count is the same as before you started, and no `[user]` quote changed. Report anything you could not check.
10. **Hand back.** Tell the user the page link and the one thing to read or answer next, in three lines or fewer. Do not restate the page in chat.
