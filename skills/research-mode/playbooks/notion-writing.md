### Notion writing

State: any. Use whenever you write a lesson or learning note the user reads and comments on in Notion: a teach lesson or an explain account. The Roadmap section (on the topic's Map of content page) and each ingested page's Understanding section are written by `make-me-roadmap` and `evaluate-my-understanding` under the same rules. Notes about a paper (README, alignment, source analysis) stay in the repo and follow the Obsidian writing playbook. Done means the page opens in Notion with its diagram showing, the user's comments untouched, and its Type and Relation properties set.

The user reads these pages beside the paper and comments on them. The page is the conversation, so the chat reply stays short. The Raw, Log and Map-of-content structure is run by the `notion-llm-wiki` skill. This playbook says how to write a page that lives there.

1. **Find the wiki, do not guess it.** Search Notion by title for the pages Raw, Log and the topic's Map of content page. If any is missing, run the initialization of the `notion-llm-wiki` skill. If that skill is not installed, say so and stop. Never write page IDs, workspace URLs or names into rstack files: rstack is mirrored publicly.
2. **Place it.** A lesson or core note is a Raw page, a child of the Raw page, titled with the date and a slug (2026-11-05_ecg-device-types). A big branch is its own Raw page. The roadmap and the understanding record are child pages of the topic's Map of content page. Start a Raw page with a short header: Source, Collected, Session date, State (open or closed), Continues (a link to the Raw page it follows, when there is one), and, for a branch, Parent and Depth. Then the Enough-means line. No front matter. After creating the page, set its properties with an update; creating it with properties does not set them: Type raw for a Raw page, Type MOC for the roadmap and understanding pages, and Relation pointing at the topic's Map of content page. Read the page back and check that both show. If the Type option you need is missing in the database, report it once and stop; do not retry.
3. **Write for a reader who is new.** Short sentences. Define a term where it first appears. Say what a word points at before using it. Label statements with the understanding ladder. Put the user's own words in quote blocks marked `[user]`, copied word for word. Write one flowing account, not boxes: define each term in the sentence where the thing first happens, with its rule or number in the same paragraph. No Definitions or Properties callouts, no list of words before the story (the `explain` skill).
4. **Draw rarely, in a `mermaid` code block.** One figure per page by default, a second only if words and the first cannot show the structure, never one per step (the `make-the-figure` skill). Notion draws a mermaid code block, so write the Mermaid text straight into the page. Keep labels short. A picture Mermaid cannot draw needs a file upload; ask the user before making one.
5. **Open and closed.** While a Raw page is open you may extend it at the end, and a branch opens as a new Raw page whose header has Parent (the page it came from) and Depth (parent's plus one, at most 3). The user's `[user]` quotes are never edited. Ingest refuses a page that still has an unanswered comment thread; answer it first. When the page is ingested (the `notion-llm-wiki` skill), its State flips to closed, a Log entry says so, and nothing in it changes afterwards. The next lesson on the topic opens a new Raw page whose Continues line links back.
6. **Leave the user's comments alone.** The user comments with Notion's own comments. Read the open threads with the Notion get-comments tool; a thread is open if it is not resolved and its last message is not yours. Reply inside the thread with the create-comment tool and the discussion id: plain words, short, in the user's language. Never resolve, delete, edit or reword a comment, even though the tools allow it. Untested: how an inline comment shows the text it points at, and the reply itself. Say so to the user the first time, and fall back to a page-level comment that names the quoted text if the inline form does not work.
7. **Edit a commented page carefully.** Extend with the insert-content command at the end. Never use the replace-content command, and never allow deleting content, on a page the user comments on. An inline insertion goes next to a commented span, never inside it. What Notion does to a thread when its text is replaced has not been tested here, so treat it as unsafe. Before an inline edit, fetch the page with discussions included to see where the comments are anchored.
8. **Keep data off the page.** Lesson text only. If the user pastes recordings, signals, subject identifiers or file listings, do not copy them into Notion; say they stay local, as the project's AGENTS.md requires.
9. **Check.** No script checks a Notion page. Read it back: the properties show, the Mermaid block shows, the comment count is the same as before you started, and no `[user]` quote changed. Report anything you could not check.
10. **Hand back.** Tell the user the page link and the one thing to read or answer next, in three lines or fewer. Do not restate the page in chat.
