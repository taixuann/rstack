# Protocol wiki

The lab's `wiki/` holds reusable protocol knowledge (workflows, procedures, equipment). It is its own git repo and has its own rules; this reference only gets you there. Reads and writes `wiki/` only; nothing leaves the machine.

1. **Navigate.** Read `wiki/CLAUDE.md` and follow its router: it names the rules and the schema for the kind of page you touch. Those outrank this guide.
2. **Work the page** with the skills that fit: `brainstorming` to generate and choose, `interrogate` in interview mode to ask the user what is missing, `doc-coauthoring` (an Anthropic skill the user installs; without it, do the same steps by hand) to build the page section by section.
3. **Guess nothing.** A missing value is `TODO: unknown` with who can answer. Take values from the user and from sources the wiki's rules allow, never from run data.
4. **Commit in the wiki repo only.** A page is a stub or a draft; only the user sets it to reviewed.

**Direction.** Wiki first: the user feeds protocols and **Experimental design** later reads them. Design first: a frozen note exists and is ingested as a workflow; ask the user to confirm each quantity before it is written.

**Reply:** the pages changed, the unknowns still open, and what you need from the user.
